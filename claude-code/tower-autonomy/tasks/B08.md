# B08 — Build representative replay fixtures

**Status:** [x] Complete by user acceptance; tier unavailable replay gap deferred
**Domain:** `foundation`
**Dependencies:** [B02](./B02.md), [B04](./B04.md)
**Dependency gate now:** [x] Satisfied — B02 and B04 are complete

## Outcome

Extend OCR fixtures with before/after action sequences and account snapshots for each supported subsystem, ambiguous reads, expensive confirmations, overlays and late-game layouts.

## Acceptance gate

Each enabled capability has positive, unavailable and ambiguous-state examples plus a reproducible focused verification command; unsupported capabilities remain disabled.

## Current repository state

- [x] Focused OCR, screen, overlay, and account-reader fixtures exist.
- [x] `tests/fixtures/replay/manifest.json` declares, for every enabled capability,
  a positive, an unavailable and an ambiguous example in one vocabulary, plus five
  recorded before/after action sequences (purchase interval, unlock restock,
  missions scroll, Settings into Stats, and a grid blinded by an info panel).
  `tests/test_fixtures.py` replays each one through the real reader and requires
  that a state the reader cannot act on never becomes a tap target or a value.
- [x] `tests/fixtures/account/` holds a golden snapshot per recorded account
  capture, digest included, so a reader change that re-classifies a field shows
  up here instead of in a run.
- [x] `screen_discovery.capabilities()['replay_coverage']` names the manifest, the
  covered capabilities and the owned gaps, so the support matrix and the fixture
  set cannot drift apart.
- [x] Referenced replay PNGs carry SHA-256, native geometry, and an explicit
  game-version value (`unknown` where the recording did not establish it).
  The Settings version is checked against its recorded OCR. The Missions replay
  recognizes a claimable card without publishing a claim action; its ambiguous
  example uses duplicate CLAIM candidates. The multi-purchase Workshop pair
  is identified as an interval, not one verified tap.
- [x] A live v29.0.2 account with history through Tier 15 adds recorded Stats
  summary/table frames, OCR and golden snapshots, plus a before/after scroll
  sequence. The reader now admits wider coin values (for example `109.71B`)
  without inferring missing cells. Stocked Cards, Modules, active Labs and a
  third, later Workshop Attack layout are recorded. Focused checks prove the
  new layouts remain refused and publish no new actions.
- [ ] Deferred acceptance gap: `account.stats.tiers` has no example of a
  present-and-not-usable tier cell. Even the progressed account draws literal
  `0` in every column beyond its recorded wave history. The reader cannot
  distinguish an unavailable tier from a trusted numeric zero or an OCR miss
  on that screen. The pre-scroll summary has no table, but that is a different
  screen, not evidence that a tier cell is unavailable. The owned gap remains
  in `replay_coverage['gaps']` rather than inventing a lock state.
- [ ] Still unrecorded, and still `unsupported`: an owned Ultimate Weapons page,
  in-run card locks, Modules banner/pity state, and native Battle History/stat
  exports. Cards identity, presets, Labs and Modules now have first captures,
  but their readers and actions remain unsupported.

B08 is marked complete at the user's explicit direction with this coverage
exception recorded. A future explicit unavailable marker or independent lock
evidence that the tier reader can safely use is still needed to close the
`account.stats.tiers.unavailable` replay gap. The reader and capability matrix
remain fail-closed for that state.
