## Current repository state

- [ ] No graph-level implementation has been certified complete.
- Landed slice: `modules.py` models the inventory — the four primary
  categories derived from the catalog's `<category>-substats` domains, assist
  as a slot role, `ambiguous`/`unknown` for disagreeing or absent evidence,
  and five separately-addressable effect channels (`main_stat`,
  `unique_effect` with rarity scaling, `substat`, `primary_effect`,
  `assist_effect`). Levels, assist levels, assist quantity and its floor,
  stars, rarity, natural-rarity provenance, shards and banner/pity state each
  keep `unknown`, `locked`, `unavailable`, `maxed` and `unreadable` apart, and
  no missing observation becomes a number.
- `AccountRevision` gained one field, `modules`, persisted and restored
  through `AccountRepository`; `AccountState.observe_modules` refuses to let
  an unread inventory overwrite a saved one.
- Not landed: there is no Modules reader. No capture of the screen exists at
  any resolution, so `modules.read_modules_screen` always refuses and
  `screen_discovery.capabilities()` now names the gap
  (`modules_screen_layout`, `modules_banner_pity_state` -> B08;
  `module_upgrade_merge_actions` -> C04). The gate's "every equipped module
  resolves to the correct category" is proven for the model, never against a
  recorded or live Modules screen.
