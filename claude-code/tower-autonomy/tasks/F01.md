## Outcome

Read wave, tier, game speed, elapsed time, health/recovery/wall state, enemy damage and modifiers, perks, cash, UW/card state and run purpose as separate observations.

## Acceptance gate

The planner detects a changed run/build and expires cached rows; decision-critical missing HUD values prevent the affected action instead of defaulting to zero.

## Current repository state

- [x] The perception loop observes current screens, OCR rows, wallet fragments, and basic run boundaries.
- [x] `combat_context.py` holds every battle fact as its own observation with its own
      state (`known` / `unknown` / `unreadable` / `expired` / `unsupported`) and its own
      freshness window. A missing fact is never a number.
- [x] `RunIdentity` (run id, account build revision, run purpose) stamps every reading and
      every cached upgrade row. A changed run or build expires them; a scan that simply does
      not know a field is not treated as a change.
- [x] `perception.parse_frame` additionally reads game speed, health recovery per second and
      the pause banner from the recorded in-run captures; `RunTracker.elapsed()` reports run
      time, and `None` while no run is open.
- [x] The planner reads its cash through the context, so an unreadable wallet refuses the
      purchase instead of spending against a stale or zeroed balance.
- [x] A changed run or build cancels pending purchase confirmation and clears cached battle
      rows before another action; a supplied observation must match the current frame.
- [x] A reading observed at time zero ages normally instead of remaining fresh forever.
- [ ] Still required: tier, perks, wall, loadout, card and Ultimate Weapon state are declared
      `unsupported` with owners (F05, F06, A02, F07, C01, U01) rather than read - no recorded
      in-run capture shows them, and tier appears only on the death modal, which describes the
      run that just ended. Enemy modifiers beyond the bounded damage figure are owned by B08.
